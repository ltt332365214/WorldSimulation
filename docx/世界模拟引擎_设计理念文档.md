# 世界模拟引擎（WorldSim Engine）
## 设计理念文档 v1.0

> 一套以"客观世界模拟"为核心目标的通用叙事游戏框架
> 技术栈：Node.js · 网页端 · 配置驱动

---

## 一、核心哲学

### 1.1 世界优先，玩家其次

本框架的根本立场是：**玩家是世界的一部分，而不是世界的中心。**

这意味着：
- 世界中的每一个 NPC，都按照自己的逻辑生活，与玩家是否在场无关
- 时间持续流动，不会因玩家未操作而暂停（除非游戏显式暂停）
- 玩家的行为是"输入"，世界的规则是"函数"，结果由规则决定，而非剧本

### 1.2 框架与内容分离

引擎本身不包含任何具体内容（没有红楼梦、没有某个村庄、没有某个人物）。
所有具体内容均通过**配置文件**注入。引擎只负责：

```
规则运行 · 时间推进 · 状态管理 · 事件调度 · 渲染接口
```

内容创作者只负责：

```
定义地图 · 定义人物 · 定义物品 · 定义事件 · 定义规则扩展包
```

### 1.3 通用行为体（Agent）模型

世界中的每一个有行为能力的存在（人、动物、甚至某些特殊物品），都是同一套 **Agent 模型** 的实例。区别只在于初始参数、属性值、以及绑定的 AI 决策规则集。

## 三、核心数据模型

### 3.1 世界状态（WorldState）

世界状态是唯一的全局真相来源，所有系统只读写这一份状态。

```
WorldState
├── clock           // 当前世界时间（年/月/日/时/分）
├── calendar        // 日历系统（节气、节日等，可配置）
├── weather         // 天气状态（可选系统）
├── maps{}          // 所有地图实例
├── agents{}        // 所有 Agent 实例（包括玩家）
├── items{}         // 所有物品实例
├── relations{}     // 关系网络（人与人之间）
├── factions{}      // 阵营/家族（可选）
└── globalFlags{}   // 全局故事旗标（用于触发剧情）
```

### 3.2 地图系统（Map）

地图分为两个层级：

**大地图（WorldMap）**
- 由若干"区域节点"构成，节点之间有连接关系（路径）
- 每个节点可以是：村庄、城镇、荒野、特殊地标等
- Agent 在节点间移动耗时，耗时由距离+角色属性决定

**室内地图（SceneMap）**
- 每个区域节点内部，由若干"场景格"组成（可以是网格，也可以是节点图）
- 每个格子有：地形类型、可通行性、归属（属于谁的家）、可交互物品列表

**地图配置示例思路（YAML/JSON）：**
```
map: 荣国府
  type: indoor
  rooms:
    - id: 怡红院
      owner: 贾宝玉
      connects_to: [大观园路径, 林黛玉院]
      items: [书架, 铜镜, 茶具]
      ambience: 温暖、略显散漫
```

### 3.3 Agent 模型

这是整套系统最核心的设计。每个 Agent 的结构如下：

```
Agent
├── identity           // 身份信息（不变量）
│   ├── id
│   ├── name
│   ├── gender
│   ├── birthdate
│   └── faction / family
│
├── attributes         // 基础属性（初始值由配置定义，后续可变）
│   ├── 体质 / 健康
│   ├── 智识
│   ├── 情感敏感度
│   ├── 社交能力
│   ├── 体力上限
│   └── （完全可扩展，由配置定义字段）
│
├── state              // 实时状态（随时间和行动变化）
│   ├── 位置 (mapId + position)
│   ├── 当前体力
│   ├── 当前情绪 (enum: 平静/高兴/悲伤/愤怒/焦虑...)
│   ├── 饥饿度
│   ├── 睡眠值
│   ├── 当前行动（ActionQueue中的当前项）
│   └── 当前意图（NPC 的短期目标）
│
├── memory             // 记忆系统
│   ├── 短期记忆（最近N个事件）
│   ├── 关键记忆（被标记的重要事件）
│   └── 对他人的印象记录
│
├── relations{}        // 与其他 Agent 的关系值
│   ├── agentId → { 好感度, 信任度, 亲密度, 关系类型 }
│
├── inventory[]        // 持有物品列表
│
├── skills{}           // 技能/能力（可选系统扩展）
│
├── actionQueue[]      // 行动队列（正在做 + 计划做）
│
└── aiProfile          // AI 决策配置（决定此 Agent 如何自主行动）
    ├── decisionRules[]    // 优先级排列的决策规则集
    ├── personality{}      // 性格参数（影响决策权重）
    └── schedule{}         // 日常作息时间表（可选）
```

**关键设计**：Agent 的属性字段由配置定义，引擎不硬编码任何具体属性名。这意味着你可以为红楼梦世界定义"诗才"、"心机"等专属属性，引擎照样能处理。

## 四、时间与行动系统

### 4.1 时间引擎

世界时间是离散推进的，每次推进一个最小时间单位（Tick）。

```
Tick 大小 = 可配置（例如：1分钟 / 5分钟 / 15分钟）
```

每个 Tick，引擎依次执行：
1. **推进时钟** → 更新昼夜、天气、节气等依赖时间的系统
2. **处理所有 Agent 的行动队列**（每个 Agent 各推进一步）
3. **检测并触发事件**（扫描所有事件条件）
4. **更新关系网络**（基于本 Tick 发生的互动）
5. **向 UI 推送状态变更**（渲染层响应）

### 4.2 行动队列（ActionQueue）

每个 Agent 维护一个行动队列，队列中的每个行动有：

```
Action
├── id              // 行动唯一标识
├── type            // 行动类型（睡觉/做饭/移动/对话/...）
├── target          // 行动目标（某个地点/某个人/某个物品）
├── duration        // 总耗时（Tick数）
├── elapsed         // 已消耗Tick数
├── progress        // 完成进度（0~1）
├── interruptible   // 是否可被打断
├── onComplete      // 完成时触发的回调/事件
├── onInterrupt     // 被打断时的处理逻辑
└── requirements    // 执行前提条件（如：需要在厨房、需要有食材）
```

**打断机制**：当一个优先级更高的事件（如有人来访、紧急状况）发生时，若当前行动标记为可中断，则当前行动暂停（保留进度），新行动插入队列前端。中断后可以选择继续或放弃。

**行动合法性校验**：每个行动在入队时校验前提条件，如不满足则行动失败并触发对应提示（"没有食材，无法做饭"）。

## 五、事件系统（Event System）

### 5.1 设计思路

事件系统是游戏叙事的核心驱动力，采用**条件-触发-效果**的三段式设计：

```
Event
├── id
├── name
├── trigger            // 触发条件（组合表达式）
│   ├── type: 时间到达 / 状态变化 / 位置相遇 / 关系达标 / 手动触发 / ...
│   └── conditions[]   // 具体条件列表（AND/OR逻辑组合）
├── priority           // 优先级（多个事件同时满足时的处理顺序）
├── repeatable         // 是否可重复触发
├── cooldown           // 冷却时间（Tick数）
├── effects[]          // 触发后的效果
│   ├── 修改属性
│   ├── 修改关系值
│   ├── 推送对话/剧情
│   ├── 生成物品
│   ├── 触发另一个事件
│   └── 设置全局旗标
└── scope              // 作用域（全局 / 局部地图 / 特定角色间）
```

### 5.2 条件表达式

条件采用声明式设计，例如（伪配置）：

```yaml
event: 宝黛初见
  trigger:
    AND:
      - agent.贾宝玉.location == 贾母正厅
      - agent.林黛玉.location == 贾母正厅
      - globalFlag.宝黛初见 == false
      - worldClock.isFirstMeeting(贾宝玉, 林黛玉)
  effects:
    - dialog: [宝黛初见对话序列]
    - relation: { from: 贾宝玉, to: 林黛玉, 好感度: +15, 亲密度: +10 }
    - setFlag: 宝黛初见 = true
```

### 5.3 事件类型

- **定时事件**：到达某个游戏时间触发（节日、生日）
- **位置事件**：Agent 进入某区域触发
- **关系事件**：关系值达到阈值触发
- **物品事件**：获得/使用某物品触发
- **剧情事件**：手动或前置事件触发的链式剧情
- **随机事件**：概率性触发（受各种参数影响）

## 六、AI 决策系统（NPC 自主行为）

### 6.1 设计哲学

NPC 的行为不是剧本驱动的，而是**规则+状态+性格**驱动的。同样的规则集，不同初始参数的人会做出不同决策。

### 6.2 决策流程

每个 Tick，NPC 的决策器运行以下流程：

```
1. 检查当前行动队列
   → 如果队列为空，进入步骤2
   → 如果队列有行动，检查是否需要打断

2. 需求评估（Needs Evaluation）
   → 扫描所有"需求"（饥饿、睡眠、社交、目标等）
   → 每个需求有当前紧迫度（urgency）
   → 紧迫度 = f(当前值, 性格参数, 上下文)

3. 决策规则匹配（Rule Matching）
   → 按优先级顺序扫描此 Agent 的决策规则集
   → 找到第一个条件满足的规则
   → 规则输出：下一步要执行的行动

4. 行动入队
   → 将决定的行动加入队列
```

### 6.3 决策规则配置示例

```yaml
aiRules:
  - id: 睡眠需求优先
    condition: state.睡眠值 < 20
    action: 去睡觉
    priority: 100

  - id: 饥饿进食
    condition: state.饥饿度 > 70
    action: 寻找食物或去厨房
    priority: 90

  - id: 日常问候
    condition:
      AND:
        - clock.hour IN [7, 8]
        - state.情绪 != 愤怒
        - 附近有关系亲近的人
    action: 向最近的亲近者打招呼
    priority: 50

  - id: 默认空闲
    condition: always
    action: 按性格做空闲活动（读书/散步/闲坐）
    priority: 1
```

### 6.4 性格参数对决策的影响

性格参数是权重调节器，不改变规则结构，只改变规则触发的阈值与倾向：

```
personality:
  外向度: 0.8        // 影响主动社交频率
  情绪稳定性: 0.4    // 影响情绪波动幅度
  勤劳度: 0.6        // 影响主动做事的意愿
  谨慎度: 0.7        // 影响风险决策倾向
```

## 七、关系网络系统

### 7.1 关系模型

```
Relation(agentA, agentB)
├── 好感度 (-100 ~ 100)
├── 信任度 (0 ~ 100)
├── 亲密度 (0 ~ 100)
├── 关系标签[]  // 朋友/恋人/夫妻/主仆/师徒/仇敌...
└── 历史记录[]  // 关键互动事件记录
```

关系是**双向但不对称**的：A对B的好感 ≠ B对A的好感。

### 7.2 关系变化规则

关系值的变化由**互动系统**和**事件系统**共同驱动：
- 对话：根据对话内容和双方性格，变化关系值
- 帮助行为：提升信任度
- 冒犯行为：降低好感度
- 时间衰减：长期不互动，亲密度缓慢下降（可配置）

## 八、对话系统

### 8.1 对话的两种模式

**剧情对话（Scripted Dialogue）**
- 由事件系统触发
- 按配置的对话树执行
- 玩家选择选项，NPC 根据选项+关系值+状态给出不同回应

**自由对话（Dynamic Dialogue）**
- 玩家主动与 NPC 互动
- 由对话系统根据 NPC 状态、关系值、当前情境生成可用话题列表
- 选择话题后，从该话题的对话模板中取出合适的回应

### 8.2 对话对关系的影响

每段对话可以标注情感标签（称赞/冒犯/诉说心事/请求/拒绝），系统根据标签和双方参数自动计算关系变化。

## 九、物品系统

### 9.1 物品模型

```
Item
├── id / name / description
├── type         // 消耗品/工具/礼物/食材/家具/...
├── properties{} // 通用键值对（完全可配置）
│   例如：{ 饱食值: 30, 烹饪材料: true, 价值: 5 }
├── location     // 当前位置（地图格子 或 某Agent的inventory）
├── owner        // 归属权
└── interactable // 可执行的互动类型（使用/赠送/查看/...）
```

物品无硬编码属性，所有属性字段由配置定义，让引擎具备处理任意类型物品的能力。

## 十、可插拔系统模块（Plugin Systems）

### 10.1 系统注册机制

引擎提供系统注册接口，任何新系统都可以以插件形式接入：

```
System 接口
├── name          // 系统名称
├── dependencies  // 依赖的其他系统
├── onInit()      // 初始化时调用
├── onTick()      // 每个Tick调用
├── onEvent()     // 监听事件总线
└── exposeAPI()   // 向外暴露此系统的操作接口
```

### 10.2 内置系统清单

| 系统 | 核心功能 | 是否强依赖 |
|------|---------|-----------|
| 昼夜系统 | 时间→光照→NPC行为影响 | 推荐 |
| 对话系统 | 玩家/NPC对话管理 | 推荐 |
| 互动系统 | Agent间/Agent与物品的互动框架 | 推荐 |
| 婚姻系统 | 关系演进、婚配条件、家庭结构 | 可选 |
| 遗传系统 | 后代属性继承逻辑 | 可选 |
| 耕作系统 | 种植、生长、收获的状态机 | 可选 |
| 战斗系统 | 回合/实时战斗框架 | 可选 |
| 经济系统 | 货币、交易、市场价格 | 可选 |

### 10.3 扩展示例：四季系统

```
四季系统 onInit():
  → 读取日历，设定季节规则

四季系统 onTick():
  → 根据当前日期更新 worldState.season
  → 触发季节相关的天气参数修改
  → 影响耕作系统的生长速率
  → 影响NPC的衣着状态、情绪倾向（可配置）

四季系统 onEvent(节气到达):
  → 触发节气活动事件
```

## 十一、玩家系统

### 11.1 玩家即 Agent

玩家控制的角色本质上是一个普通 Agent，不同点仅在于：

```
player.controlled = true
```

当 `controlled = true` 时：
- 行动不由 AI 决策器决定，而是等待玩家输入
- 界面层显示玩家可执行的操作列表

### 11.2 玩家操作体验

玩家通过点击操作：
1. 查看当前场景（地图视图）
2. 点击场景中的 Agent / 物品 / 出口
3. 弹出上下文操作菜单（可做的事情列表，由引擎根据当前状态动态生成）
4. 选择操作后，行动入队，时间推进

### 11.3 世界时间与玩家操作

两种时间模式（可配置）：
- **回合制**：玩家每次操作后，世界推进相应Tick
- **实时暂停制**：世界自动推进，玩家可随时暂停并操作

## 十三、渲染与交互层设计原则

引擎与 UI 完全解耦，引擎只暴露：
- 当前世界状态快照（State Snapshot）
- 玩家可执行的操作列表（Available Actions）
- 事件/对话推送（Event Stream）

UI 层负责将上述数据渲染为用户可交互的界面。这意味着：同一套引擎可以搭配不同的 UI（文字冒险风格、像素地图风格、纯对话框风格等）。

---

## 十四、扩展性原则总结

| 维度 | 扩展方式 |
|------|---------|
| 添加新属性 | 在 `_template.yaml` 增加字段，无需改引擎代码 |
| 添加新系统 | 实现 System 接口，注册到 `systems.yaml` |
| 添加新行动类型 | 在行动注册表中注册，定义耗时/前提/效果 |
| 添加新事件条件 | 在条件解析器中注册新条件函数 |
| 更换整个世界 | 替换 `/world-config/` 目录 |
| 更换 AI 决策 | 替换 `aiRules` 配置或接入外部 AI 模块 |

## 十五、红楼梦世界注入示例（设想）

```
world.yaml        → 清代时间体系、节气、货币单位
maps/             → 荣国府、大观园、宁国府等室内地图
agents/           → 贾宝玉、林黛玉、薛宝钗、王熙凤...（各40+配置项）
events/           → 葬花、共读西厢、宝黛吵架、元妃省亲...
systems/          → 启用：昼夜、对话、关系、婚姻、遗传、经济
```

玩家选择扮演任意一人（宝玉、黛玉、甚至一个丫鬟），进入这个世界，体验其人生轨迹，同时可以通过自己的选择，影响、甚至改变原著的走向。
